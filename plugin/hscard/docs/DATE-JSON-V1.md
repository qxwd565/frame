# HScard: 날짜 최상위 키 카드 JSON 전용 (dates-v1)

## 필수 형식

각 원본 카드 파일은 기존 경로 `data/<CARD_ID>.json`을 그대로 사용합니다.

```json
{
  "2013-08-17": {
    "name": "별빛 수호자", "type": "MINION", "mana": 5,
    "attack": 4, "health": 6, "text": "도발", "cardClass": "NEUTRAL",
    "rarity": "COMMON", "races": []
  },
  "2014-01-17": {"mana": 6},
  "2015-04-01": {"mana": 0, "text": ""},
  "2020-01-01": {"race": null}
}
```

실제 출시/패치 날짜는 위 예시와 무관합니다. 날짜는 한국 달력의 `YYYY-MM-DD` 문자열입니다. 맨 처음 날짜에는 카드 이름과 유형을 비롯한 실제 필요한 초기 필드를 채웁니다. 다음 기록은 바뀐 필드만 포함합니다.

- 매 날짜까지의 변경 사항을 오름차순으로 누적하여 카드 상태를 얻습니다. 미래 패치는 무시하며 최초 기록 전에는 카드가 존재하지 않습니다.
- 숫자 `0`, `false`, 빈 문자열 `""`, 빈 배열 `[]`은 변경값으로 인정합니다.
- `null`은 해당 필드 삭제입니다. 중첩 객체/배열은 전체를 교체하며 깊은 병합을 수행하지 않습니다.
- 비용은 `mana` 또는 `cost`를 지원합니다. 서로 다른 날짜에 혼용돼도 마지막 변경값이 우선합니다.
- 비날짜 최상위 `meta`/`metadata` 등은 날짜별 카드 스탯에 자동 적용하지 않습니다. 신형 스키마만 허용하며 구형 `card`, `patches`, `history` 객체는 거부합니다.
- 타입별 스탯: MINION(attack, health), SPELL, WEAPON(attack, durability), HERO(armor), LOCATION(durability), HERO_POWER, ENCHANTMENT. 기타 실제 저장 필드는 누락 없이 내부 상태에 보존합니다. 원본의 3D 렌더러가 지원하지 않는 타입은 그대로 지원 범위 밖입니다.

## 구현 흐름

1. PHP는 `cards.json`을 카드 DBF ID·카드 ID·세트의 **목록 데이터**로만 사용합니다. 날짜별 정보의 출처는 아닙니다.
2. 카드의 정확한 출처가 확인되면 PHP가 `data/<CARD_ID>.json` URL을 HTML 속성에 전달합니다. 전체 저장소 조회 폴백은 사용하지 않습니다.
3. `assets/unity/card-snapshots.mjs`가 유일한 날짜 스냅샷 복원 모듈입니다. HTTP URL당 원본 JSON 한 번 요청하고 같은 카드+날짜 결과를 재사용합니다. 동시에 준비하는 요청은 최대 8개입니다.
4. `card-data.mjs`와 `deck-hydration.mjs`가 복원된 동일 데이터를 공유합니다. 모바일 덱 타일과 데스크톱 WebGPU 카드가 같은 날짜 정보로 갱신됩니다.
5. 관리자 화면 `JSON 관리 → 날짜별 카드 JSON`에서 로컬 카드 파일의 날짜별 내용을 저장할 수 있습니다. 원격 GitHub 소스는 해당 저장소의 기존 파일을 수정해야 합니다.

## 현 상태의 제약

**WebGPU 시험판입니다.** WebGPU WGSL 전체 컴파일·실제 카드 이미지/황금 애니메이션 검증이 완료되지 않았으며 운영 서버 설치용으로 검증되지 않았습니다. 그림/메쉬/셰이더 코드는 이 JSON 구조 변경에서 다시 작성하지 않았습니다.

**현재 원격 API가 날짜 최상위 키 형식으로 변경되기 전에는 원격 카드를 정상적으로 표시할 수 없습니다.** 구형 데이터로 카드 상태를 대신 채우지 않도록 의도된 동작입니다.

원본 캐시는 페이지 수명 동안 공유됩니다. URL에 버전 토큰이 있다면 다른 버전은 별개 캐시로 처리하고, 관리자 변경 후에는 새로고침하여 갱신합니다. 공식 출처가 원본 버전 식별자를 제공하지 않으면 열린 페이지에서 자동 실시간 갱신되는 것은 아닙니다.
