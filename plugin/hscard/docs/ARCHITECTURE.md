# HSdeck HScard 데이터 아키텍처 (7.14.4 시험판)

신규 데이터 구조는 `docs/DATE-JSON-V1.md`를 참조하십시오.

- 워드프레스 카드 저장소: 기존 DBF ID와 카드 ID 매핑, 세트별 목록, 원화 출처, 부모/자식 연결을 관리합니다.
- `cards.json`: 데이터베이스 인벤토리 및 카드 ID-세트 연결 용도만 사용합니다. 날짜별 카드 상태의 원본이 아닙니다.
- `data/<CARD_ID>.json`: 날짜 최상위 키로 저장한 유일한 카드 상태 원본입니다. 구형 `card`/`patches`/`history.json` 병합 불가.
- PHP `Deck_View`/`Render_Spec`: 카드의 DBF ID·원본 ID, 날짜, HTML 골격, 프레임 선택값, 정확한 JSON URL만 전달합니다.
- JS `card-snapshots.mjs`: 원본 네트워크 캐시 + 카드/날짜 스냅샷 캐시, 델타 정렬, 얕은 교체, 삭제, 카드 유형별 정규화 담당.
- JS `card-data.mjs`: 복원된 스냅샷을 기존 WebGPU 카드 렌더러가 이해하는 입력으로 변환하며 원화만 필요시 보충합니다.
- JS `deck-hydration.mjs`: 모바일 덱 목록 및 HTML 카드 메타데이터를 스냅샷과 일치시키고 날짜 변경 시 다시 적용합니다.
- WebGPU 렌더러는 현재 설치된 게임의 DXBC를 HLSLcc와 Naga로 빌드 시 변환한 WGSL을 사용합니다. 브라우저에서는 작은 인덱스와 필요한 WGSL 파일만 읽고 SHA-256을 확인합니다.
- 원본 메시·텍스처·폰트·과거 프레임 데이터는 `qxwd565/frame`의 별도 버전 경로에 있습니다. 플러그인 ZIP에는 PHP·브라우저 코드·정적 로딩 미리보기만 포함합니다.
- 모든 카드가 WebGPU 장치와 캔버스를 공유합니다. 원본 재질 바인딩과 시간 값을 보존하며 페이지 종료·장치 손실·카드 제거 시 GPU 자원을 해제합니다.

같은 날짜 상태를 PHP와 JS에서 각각 누적 복원하지 않습니다. 날짜는 웹 브라우저의 현지 시차로 이동하지 않는 달력 문자열로 비교합니다.

### 주요 한계

정확한 카드 출처를 파악할 수 없을 때 외부 API 51개를 순회하지 않으며 오류를 표시합니다. 카드 유형 `HERO_POWER`/`ENCHANTMENT` 데이터 정규화는 지원하지만, 해당 유형의 3D 렌더링은 기존 백엔드 지원 범위를 따릅니다. 실제 WGSL 컴파일·파이프라인·카드 출력은 검증했고, 게임 화면 직접 비교와 실서버 WordPress 검증은 남아 있습니다. 측정 범위는 `WEBGPU-STAGING-STATUS.md`를 확인하세요.
