# WebGPU 검증 현황 — 2026-11-09 KST

HScard 7.14.4-webgpu-dates-v1-preview. 운영 반영 완료가 아닌 검증용 브랜치입니다.
기존 main과 운영 CDN은 바꾸지 않았습니다.

## 구현

- 사용자가 교체한 최신 7.14.4 ZIP을 기준으로 PHP/API/날짜별 데이터를 유지했습니다.
- 현재 설치 게임(Unity 6000.3.11.3145967)의 셰이더를 새로 추출했습니다.
  이것은 Unity 빌드 번호이며 하스스톤 패치 버전이 아닙니다.
- DXBC → Unity HLSLcc → Naga 검증 → WGSL은 빌드 시 실행합니다.
  브라우저는 WGSL을 device.createShaderModule()로 컴파일합니다.
  WebGL 엔진, GLSL 코드 묶음, 옛 엔진 셰이더는 배포하지 않습니다.
- 원본 상수 버퍼·텍스처/샘플러 슬롯·UV·밉맵·혼합·깊이·스텐실·시간 값을 연결했습니다.
  압축 BC 텍스처의 작은 mip 업로드, 비교 샘플러 깊이 업로드,
  이름 RTT 방향, 비동기 파이프라인 대기 문제를 수정했습니다.
- 3664/3890의 메시·텍스처·글자 배치와 이후 역사적 부품을 유지합니다.
  구형 셰이더 이름은 현재 게임의 대응 셰이더로 연결합니다.
- GPU 텍스처 예산은 실제 업로드 형식의 mip 크기로 계산합니다.
  원본 텍스처 다운로드/디코딩을 공유하고 uniform 업로드를 장면마다 묶습니다.
- 장치 손실 시 한 번 복구하며 이전 장치 자원을 해제합니다.

## 성능 측정의 범위와 정정

Windows/Chrome headless, NVIDIA Pascal, 436×682 타깃, 로컬 HTTP 리소스,
30장 중 15장 황금, 준비 이후 애니메이션 프레임을 8회 측정했습니다.
텍스처 공유 방식은 실제 페이지와 동일합니다. 아래는 교대로 3회 실행한 중앙값입니다.

| 항목 | 최적화 전 | 최적화 후 |
| --- | ---: | ---: |
| 첫 카드 준비/출력 | 229.4ms | 255.8ms |
| 30장 준비/출력 | 599.3ms | 683.2ms |
| 애니메이션 프레임 | 15.3ms | 14.5ms |
| present-only 스크롤 | 2.7ms | 3.0ms |

차이가 작고 초기 준비는 느려진 측정도 있어 전체 성능 향상으로 판정하지 않습니다.
기존 약 10FPS 결과는 검사 코드가 페이지의 공용 텍스처 캐시를 빠뜨린 결과입니다.
수정 후 프레임 측정 범위는 14.1–15.5ms(약 65–71FPS)입니다.
이는 서로 다른 30장의 실 사이트 성능이나 모든 기기에서의 60FPS 보장이 아닙니다.
초기 리소스/API 로딩은 이 구간 밖이며, 별도 CDN 진입 검사 10장 로딩은 8.23초였습니다.

카드 30장을 제거하고 다시 5장씩 3회 준비/제거한 후 캐시 보유 개수는
동일했습니다. renderer.dispose() 뒤 추적 자원은 모두 0개였습니다.
업로드 mip payload 약 50.1MiB는 드라이버 VRAM 전체 측정치가 아닙니다.

### 일반 카드 애니메이션 복원 — 2026-11-09

일반 카드를 정지 화면으로 취급하던 스케줄러 조건을 수정했습니다. 실제로
선택된 셰이더의 시간 입력과 재질 애니메이션을 기준으로 갱신하며, 일반·황금
모두 화면 밖에서는 시계를 멈춥니다. 셰이더 계산식이나 원본 리소스는 그대로입니다.
현재·3664·3890 일반 하수인의 마나/공격력/생명력과 구형 주문·무기의 마나
영역을 서로 다른 시간에 GPU에서 읽어 픽셀 변화를 확인했습니다. 희귀도 보석도
동일한 원본 효과를 사용합니다. 일반 카드 반복 갱신·화면 밖 정지·황금 왕복·
호버·장치 손실 복구 검사가 통과했습니다. 위의 과거 15/30장 애니메이션 성능
측정은 일반 능력치 효과를 포함하지 않은 수치입니다.

### 2026-11-09 실제 사이트 캐시 문제

`hsdeck.com/closed-beta/rogue/`에는 새 파일이 설치됐지만 WordPress.com의
압축 응답 캐시가 같은 버전 URL에 예전 실행 코드를 반환했습니다. 그 코드가
삭제된 `webgpu/wgsl-programs.json.gz`를 요청해 404로 멈췄습니다.
공개 페이지 HTML의 실행 코드 URL만 새 쿼리로 바꾸는 브라우저 대조에서는
사이트에 설치된 코드와 실제 CDN/API로 카드 50개 모두 출력됐습니다.
수정한 로컬 JS/CSS를 같은 DOM에 대입한 검사도 50/50 성공했습니다.
이는 서버 파일을 직접 교체한 검사가 아닙니다.

이제 ZIP 생성 시 전체 모듈에 내용 해시를 붙이고, PHP도 실행 코드 해시를
JS/CSS URL에 붙입니다. 플러그인 버전은 유지합니다. 반복 빌드, 모듈만 수정,
CSS만 수정한 경우와 상대 모듈 참조 36개를 검사했습니다. 일반·황금 왕복과
장치 복구 검사도 다시 통과했습니다. 서버 재설치 후 확인은 남아 있습니다.

- 원본 인게임 직접 캡처와 비교하고 베타 프레임 출력 차이 해소.
